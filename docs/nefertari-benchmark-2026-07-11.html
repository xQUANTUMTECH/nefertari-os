Metodo

Due tasse da misurare, un verdetto che non si discute

Bench A — la tassa dei round-trip

Creare 6 file con contenuto esatto. single: una fs_write per file (plan_run nascosto al modello). plan: tutto in UNA chiamata plan_run transazionale.

Bench B — la tassa del percorso unico

Trovare quale di 3 tagline passa un test di accettazione (grep). seq: prova-verifica-riprova, una alla volta. traj: UNA trajectories_run ×3 fork paralleli + promote del vincitore.

Regole di onestà

  • Successo fisico: si verificano i file su disco, mai le parole del modello.
  • Token reali: campo usage dell'API, prompt + completion.
  • Tool nascosti per modalità: rimossi dalla lista tool; se allucinati, guard che risponde "not available".
  • Ambiente fresco per run: workspace, NEFERTARI_HOME e server MCP nuovi ogni volta.
  • Enforcer Landlock attivo sulle shell reversibili, broker su ogni azione.

Cosa succedeva

checkpoint() e fork() creavano tree/ solo copiando file: workspace vuoto = ENOENT sul manifest. Entrambi i modelli, indipendentemente, hanno bruciato ~8 turni (ls, timeline_list, mkdir…) prima di trovare da soli il workaround: un file placeholder e ri-checkpoint.

Il fix (una riga ×2) + regressione

mkdirSync(tree, {recursive:true}) prima della copia, in checkpoint e fork. Test nuovo: dir vuota → checkpoint / fork / promote. Suite 9/9 PASS. Commit 3a845c4. È esattamente ciò che un benchmark reale deve produrre.

Letture oneste

Cosa dicono davvero questi numeri

Dove le primitive vincono

  • traj ha costo costante; seq scala linearmente coi tentativi. Con K candidati e eval costose (test suite reali) il divario esplode a favore dei fork paralleli.
  • plan: 1 chiamata invece di N, wall più basso, e rollback atomico che nessuna sequenza di write singole può dare.
  • Ogni fork ha enforcement gratis: le shell degli step girano con cwd nel fork, Landlock confina le scritture lì.
  • Il journal registra tutto: winner, fork, piano, classe — auditabilità che il modo "flat" non produce.

Dove essere cauti

  • Il parallel tool calling mitiga già la tassa dei round-trip sui batch piatti e indipendenti: lì plan_run vince di poco.
  • traj costa più token quando il sequenziale avrebbe indovinato presto (deepseek: 21k vs 13.6k) — è un'assicurazione, si paga.
  • Gli argomenti JSON annidati di plan/traj sono fragili per alcuni modelli: deepseek in run precedenti ha emesso markup DSML e args vuoti (2 retry) — varianza, non determinismo. In questi run finali: primo colpo per entrambi.
  • Campione piccolo: 1 run per cella, 2 modelli, task brevi. Direzione chiara, grandezze indicative.
